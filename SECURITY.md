# Security policy

Report vulnerabilities privately using GitHub's **Security → Report a vulnerability**
for this repository. Do not put credentials, exploit details, or private repository
data into a public issue. Ordinary bugs belong in the issue tracker.

Include the affected commit/version, impact, reproduction steps, and relevant
logs with credentials removed. The maintainer will assess the report and coordinate
remediation and disclosure through the private report.

Security fixes target the current maintained version. Consumers pinned to older
commits must update their pin to receive fixes; historical pins are not patched
in place. Release notes will identify assigned vulnerability identifiers where
applicable. A response within 14 days is the project's response target; evidence
of actual response times must be assessed during Best Practices review.

See [the trust model](docs/security-model.md) for the automation's boundaries.
