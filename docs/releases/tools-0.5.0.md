# Tools 0.5.0

The shared lifecycle adds `release-plan`, `release-operations`,
`lifecycle-github`, `lifecycle-transport`, `lifecycle-pages` and `release-admit`. One selected
package compiler and immutable plan drive source checks, native host adapters,
common asset preparation, SBOM generation, sealing and tests of the exact
candidate bytes. A reusable workflow supplies the job graph and one aggregate
verdict. Consumers declare inert topology and bounded product tasks.

Admission independently reads GitHub job and artifact identities and checks the
complete obligation set, original producer, transport digest, final inventory,
SBOM bindings and bundle members. Host linker inputs remain intermediates;
published native binaries require a candidate execution obligation. Publication
runs reviewed pinned code without a consumer checkout, rechecks admission,
verifies provenance and delegates draft staging and hash readback to the shared
publisher. Optional Pages deployment restores the admitted documentation ZIP.

The native release pipeline tests the exact Linux, Apple Silicon and Windows utilities using an independent
harness without a source checkout or compiler. Additional native CI and real
consumer fixtures record their actual target execution scope. Those tests do
not establish consumer environment protection or protected release success;
those require observations from the consuming repository. Downstream pilot
migrations are follow-ups.

Compatibility fixes accept the flattened result file produced by a single-target
artifact download while rejecting ambiguous duplicates before decoding either
layout, including malformed or nonregular duplicate entries. Compiler checks and
builds require exit code 0; warning status 2 remains a failure with raw diagnostics
preserved so the emitting source or dependency can be corrected. Downstream
compatibility badges accept inline comments after pinned workflow references.
Examples may opt into
`--fuzz` builds and per-case ignored stderr. Fuzz builds use the compiler's LLVM
backend and retain bounded process, output and timeout handling. Explicit local
expectation updates share the same engine, reject CI and published suites, and
replace the complete spec only after successful cases and a final source check.
Optional stdout normalization removes SGR sequences and carriage returns only
for comparison; raw diagnostics remain intact. Real replay and
failure probes accompany the shared runner regressions.

Blueprint setup supports reviewed Windows executables and rejects Nix installation
on Windows before making requests. Executable caches are keyed by reviewed
release digests and rehashed on reuse. SBOM source archive enumeration excludes
ZIP and PDF subjects. SemVer prereleases retain hyphens while numeric identifiers
reject leading zeroes. The corrected upstream SBOM model must be adopted from a
published immutable release; merged upstream source is not a released tool.

The renderer delegates source include selection to the pinned roc-parser 3.0.0
API, retaining tagged regions, line selections and strict failure handling.
Document heading identity uses the first title, preventing a nested title from
being mistaken for another included document. HTML preserves noncolliding legacy
heading aliases after explicit-ID heading renames; canonical routes and PDF/Markdown
destinations remain unchanged.
